# Issue Splitter Rules

## 목적

한 문장에 섞인 금융상품과 문제를 독립적인 민원 사건으로 분리한다.

## 분리 기준

- 해결하려는 조치가 다르면 분리한다.
- 중심 계약·거래·통지서가 다르면 분리한다.
- 적용 규정 또는 필요한 증빙이 다르면 분리한다.
- 같은 사건의 원인과 결과는 하나의 민원에 유지한다.
- 상품명만 다르고 같은 거래라면 성급하게 분리하지 않는다.

## 분류 우선순위

1. 사용자의 명시적 문제
2. 사건·거래·계약의 구분
3. 상품
4. 요청한 해결 조치

상품명만 보고 쟁점을 추측하지 않는다.

## 출력

```json
{
  "issues": [
    {
      "issue_id": "issue_001",
      "product": "예금",
      "issue_type": "인출제한",
      "text_span": "...",
      "requested_remedy": "...",
      "shared_context_refs": []
    }
  ],
  "unresolved_parts": []
}
```

## 실패 처리

- 문장 하나를 임의로 여러 민원으로 쪼개지 않는다.
- 분리 기준이 불명확하면 `unresolved_parts`에 남기고 `ask`를 제안한다.
- 복합 민원의 각 issue에 원문 span을 남긴다.
