# Response Composer Rules

## 목적

민원별 검증 결과를 섞지 않고, 사용자가 이해할 수 있는 해결 방안과 절차로 통합한다.

## 민원별 답변 형식

```text
### 민원 1: [상품 / 쟁점]

- 현재 확인된 내용
- 관련 규정·약관·사례
- 현재 판단
- 부족한 정보
- 권장 다음 단계
- 제출 서류
- 개인정보 주의사항
```

## 필수 규칙

- 각 판단 문장에 근거 위치를 연결한다.
- 근거가 없는 법률 용어와 기관 처리 기간을 만들어내지 않는다.
- `ask`이면 질문을 최대 3개로 줄이고, 왜 필요한지 설명한다.
- `ask`이면 질문을 최대 3개로 줄이고, 왜 필요한지 설명한다. Finance MCP에 확인된 사실이 있으면 질문에 그 값을 먼저 포함하고 같은 사실을 다시 묻지 않는다.
- `hold`이면 보류 사유와 사람이 확인할 항목을 표시한다.
- `amend`이면 마스킹·보완할 항목을 먼저 안내한다.
- 여러 민원의 서류와 절차를 하나의 목록으로 합치지 않는다.

## 쉬운 설명

처음 등장하는 용어는 다음 형식으로 설명한다.

```text
우대금리: 기본 이율에 특정 조건을 충족했을 때 추가로 적용되는 이율입니다.
```

## 답변 마무리

항상 다음 세 가지를 분리해 제공한다.

1. 지금 할 일
2. 준비할 서류
3. 확인되지 않아 추가 확인이 필요한 부분
